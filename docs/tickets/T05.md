# T05 — Admin authentication

**Depends on**: T04.

## Goal

Protect `apps/admin` and the `/v1/admin/*` API surface before any editorial
tooling exists to protect.

## Scope

- Admin roles (e.g. editor, admin) with RBAC on every `/v1/admin/*` route.
- Session handling with short-lived tokens; structure it so MFA can be
  turned on later without a redesign (§16 says "MFA-ready" for admin
  sessions, not necessarily MFA in this ticket — check `PROGRESS.md`/ADR-006
  if this has been decided already).
- Rate limiting on the admin auth endpoint(s).
- This ticket is also the trigger for **ADR-006 (account/privacy
  architecture)** — if end-user auth (not just admin) design isn't settled
  yet, write that ADR now covering: whether end users get accounts at all in
  V1, how "browse without login" + optional account coexist, and how
  account deletion (§5.5) will be implemented. Do not implement end-user
  auth itself unless a ticket calls for it — this ticket is admin-only.

## Out of scope

End-user-facing login flows for the public site/app (browsing works without
login per the non-negotiables; if/when end-user accounts are built, that's
scoped by ADR-006 and a later ticket, not this one).

## Acceptance criteria

- `/v1/admin/*` routes reject unauthenticated/unauthorized requests.
- A seeded admin user can log in and reach `apps/admin`.
- ADR-006 exists (at least in "proposed" status) addressing end-user
  account/privacy architecture.
- Rate limiting on admin login is tested (e.g. Nth attempt in a window is
  rejected).
