# T09 — Dedup + clustering

**Depends on**: T08.

## Goal

Turn normalized `SourceItem`s into `Story` clusters without needing an AI
call for the common case.

## Scope

- Per §7.2 model routing: dedup/clustering uses fingerprint + lexical
  similarity **first**; only escalate to an embedding/model call for
  genuinely ambiguous pairs. Implement the deterministic path fully before
  wiring any AI escalation (AI gateway itself isn't ready until T10 — if this
  ticket lands first, stub the escalation path behind a clear TODO/interface
  that T10/T11 fill in, don't block on it).
- Fingerprinting: stable hash of normalized title/content
  (`SourceItem.raw_hash` from the schema) used for near-duplicate detection
  across sources reporting the same underlying event.
- Clustering: group `SourceItem`s into a `Story` + `StorySource` links with
  `evidence_rank`, advancing the ingestion state machine to `CLUSTERED`.
- This is deterministic, testable logic — per the engineering defaults in
  `docs/NON_NEGOTIABLES.md`, prefer it over any LLM call here.

## Acceptance criteria

- Two source items describing the same underlying event (from fixtures)
  cluster into one `Story` with both linked via `StorySource`.
- Two unrelated items never cluster together (negative-case test).
- Clustering is idempotent — re-running it on the same input doesn't create
  duplicate `Story` rows or duplicate `StorySource` links.
