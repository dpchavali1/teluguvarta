# T10 — AI provider gateway

**Depends on**: T04.

## Goal

Build the single chokepoint through which every AI call in the system must
pass — this is the trigger for **ADR-001 (AI provider selection)**.

## Scope

- `packages/ai`: an internal gateway exposing task-shaped interfaces (not a
  passthrough to any provider SDK) for each task in §7.2's routing table:
  language detection, relevance/categorization, dedup/clustering escalation,
  summary, "why this matters", English→Telugu translation, sensitive
  validation.
- Per-task default/escalation model routing exactly as specified in §7.2 —
  e.g. summary defaults to a low-cost fast model, escalates to a quality
  model only if validation fails; sensitive validation always escalates to
  human review in V1 regardless of model confidence.
- Structured output contract from §7.3: every generation call returns
  `{ relevant, confidence, categories[], countries[], entities[],
  sensitivity, urgency, summary_en, why_matters_en, claims[], source_refs[],
  publish_recommendation }`, schema-validated before it's trusted by any
  caller.
- AI failure behavior from §7.5: schema validation failure → retry once
  with a constrained prompt → otherwise hold; low confidence → review queue;
  unsupported factual claim → remove claim or hold; model unavailable → do
  not invent content, queue for later; cost threshold breached → degrade to
  classification-only mode.
- Cost telemetry: record tokens/cost per task/provider/story/day, feeding
  `MONTHLY_AI_BUDGET_USD`/`DAILY_AI_ALERT_USD` guardrails (§19). No
  provider SDK types or client objects may be imported outside
  `packages/ai` — grep for provider SDK imports elsewhere as part of review.
- Write ADR-001: which provider(s) are primary/fallback, why, and how
  provider-agnosticism is preserved (per the spec's "no provider hard-coded
  into product logic" decision).

## Acceptance criteria

- ADR-001 exists and is accepted.
- No file outside `packages/ai` imports a provider SDK (enforced by a lint
  rule or an explicit CI grep check).
- Each failure mode in §7.5 has a corresponding test.
- Cost telemetry is recorded for every call and queryable per task/day.
- Crossing a configured cost threshold measurably degrades behavior
  (classification-only mode) rather than continuing to spend.
