## Follow-up: language hydration stability (owner continued 2026-10-01)

The local UI14 matrix measured Telugu detail CLS up to ~0.217: SSR paints
English, then the stored Telugu preference replaces headline/deck/why content.
Fix this presentation transition within the existing browser-local preference
model. No cookies, server personalization, new infrastructure, new translations
or changes to variant QA/English-canonical metadata.

Render the available bilingual headline/deck/why copy in SSR HTML and expose
one language through CSS. Read the existing localStorage preference in the head
before first paint; invalid/unreadable storage defaults to English. Keep a single
set of actions, one accessible headline, correct language tags, full source links,
and a visible English fallback when Telugu is absent. Header/detail controls,
onboarding updates and cross-tab storage events must keep copy and action labels
consistent. A choice that cannot persist still works in the current session.

Verify static Home's English SSR with scripts disabled and dynamic detail's
Telugu copy with React bundles blocked (its existing streamed boundary still
requires inline completion scripts). Test preference corruption/storage failure,
switching, fallback and quota-failure language retention through onboarding.
Compare cold and previously visited-page CLS against an isolated copy of the
pre-fix working tree with the same fixtures. Run lint/typecheck/unit tests/build
and responsive/axe checks; report HTML/JS/font cost and measured limits. Do not
declare production/device performance acceptance from local measurements.
