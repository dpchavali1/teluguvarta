# S2 — Student topics and independent alerts

**Depends on**: S1. **Insert after**: S1.

## Goal

Give students a dedicated topic taxonomy and notification controls that
don't interfere with general topic alerts.

## Scope

- Student topic taxonomy per §3.1: F-1, CPT, OPT, STEM OPT, H-1B transition,
  internships, university policy, campus safety, taxes, housing,
  scholarships, travel, student community, international-student jobs. Model
  these as regular `Topic` rows (reuse T03's `Topic`/`UserTopic` tables) so
  they flow through the existing ranking/notification systems — no separate
  topic model.
- Independent alert controls per §9.4/§17: student and official-channel
  alerts are independently optional, matched against explicit user-selected
  topics/entities/life-stage, and apply the **same** quality threshold,
  quiet hours, daily caps, and deduplication as any other notification
  (T17) — no special-cased notification path for students.

## Acceptance criteria

- All student topics exist as standard `Topic` rows and are selectable in
  onboarding/settings alongside general topics.
- A student subscribed to "F-1/OPT transition" alerts receives eligible
  notifications through the exact same `notification_dispatch` worker and
  dedupe/quiet-hour/cap logic as T17's general topic alerts (no parallel
  code path).
- Unsubscribing from all student topics doesn't affect general topic
  notification settings, and vice versa.
