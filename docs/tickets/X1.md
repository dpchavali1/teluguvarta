# X1 — X source registry fields

**Depends on**: T06. **Insert after**: T06, before X2.

## Goal

Extend the source registry to hold what the X official-account adapter
needs, without touching general source logic.

## Scope

- Add to `Source` (or a linked `XAccount` table — either is fine, pick
  whichever keeps the schema cleanest): `x_user_id, handle, priority,
  rights_status` (reuse the existing enum — defaults to `DISABLED`),
  `polling_cadence, since_id, active, last_success_at, last_error_at,
  budget_class`.
- Credentials for the X API live only in the secret manager configured in
  T02 — never in the database or in code.
- Admin must explicitly approve each account and record its stable X user
  ID (§6.3.1) — reuse the same rights-evidence requirement pattern from T06
  (ADR-002), don't invent a parallel approval flow.

## Acceptance criteria

- An X account cannot be marked active/pollable without going through the
  same rights-evidence requirement as any other source.
- `since_id` and health fields exist and are queryable via the admin API for
  X4 to surface later.
- No X API credential appears in the database schema or version control.
