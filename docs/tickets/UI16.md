# UI16 — one clear Alerts setting

Owner-requested 2026-10-02 follow-up to T17 and UI15. The Settings tab had
two near-duplicate rows: an empty notification inbox placeholder and the
working preference controls. Replace them with one Alerts destination that
opens the existing settings and preserves stored preferences. Explain the
master switch, visually and functionally pause dependent controls when it is
off, and show honest delivery/permission guidance without claiming push is
live. Keep breaking, briefing, topic, student-topic, quiet-hour, and daily-cap
options. The API currently stores quiet hours as whole hours, so the UI must
not imply minute-level control. Topic switches must reflect actual stored
subscriptions, and a failed server sync must be visible with a retry action.

Acceptance: Settings has one Alerts row and no empty inbox path; existing
preference data and server sync remain; master-off keeps child choices for
later but prevents editing them; hour and cap controls are usable with 44pt
targets and screen-reader labels. Verify mobile tests, typecheck and bundle.
Real-device and live push-delivery acceptance remain separate.

Owner's 2026-10-02 device feedback: the topic list was too long and pushed
"Pause overnight" out of reach. Put timing before topics. Add an accessible
topic search that filters both general and student topics without changing
saved choices, plus a selected-only view so enabled alerts are quick to turn
off. Keep toggles usable while the keyboard is open. Verify on the attached
Android device as well as in tests.
