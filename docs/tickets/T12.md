# T12 — Editorial workflow

**Depends on**: T11.

## Goal

Give human editors the review/approve/correct/retract tooling the pipeline
needs before anything sensitive can go live, with a full audit trail.

## Scope

- Review queue UI (`apps/admin`) and API (`/v1/admin/review-queue`,
  `/v1/admin/stories/{id}/approve|reject|retract|correct`) per §9.3 admin
  surfaces and §15 review-screen requirements: source + rights state,
  original metadata, story cluster, claim/evidence pairs side by side (§7.4
  — required for high-risk categories), AI draft, sensitivity labels,
  publish controls, correction/retract controls, audit trail.
- Publication state machine transitions (approve → `APPROVED`/`SCHEDULED`;
  reject → back to draft or archived; retract → `RETRACTED`; correct →
  `UPDATED`/`CORRECTION_PENDING` → `UPDATED`) enforced server-side, matching
  T03's state machine exactly — the admin UI must not be able to force an
  illegal transition.
- Corrections: every correction creates a `Correction` row (`old_text_hash`,
  `new_text_hash`, `reason`, `created_by`) and must be able to trigger
  Telugu-variant invalidation (wire the hook now; T13 implements the
  regeneration side).
- `AuditEvent` written for every admin mutation (`actor, action, entity_type,
  entity_id, metadata, created_at`) — no exceptions.
- Operator kill switches from §15: `AUTO_PUBLISH_GLOBAL`,
  `AUTO_PUBLISH_CATEGORY_IMMIGRATION` actually gate the auto-publish path
  from T11, not just exist as unused config.

## Acceptance criteria

- An editor can approve, reject, retract, and correct a story through the
  admin UI, each producing correct state transitions and an `AuditEvent`.
- Attempting an illegal state transition (e.g. approving an already
  `RETRACTED` story) is rejected with a clear error.
- Toggling `AUTO_PUBLISH_GLOBAL` off measurably stops auto-publication
  system-wide; toggling `AUTO_PUBLISH_CATEGORY_IMMIGRATION` has no effect
  since immigration is never auto-published anyway (should be a no-op, not
  an error).
- Every mutation above has an `AuditEvent` with correct actor/action.
