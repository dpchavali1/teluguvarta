# T16 — Personalization / ranking

**Depends on**: T14, T15.

## Goal

Replace generic feed ordering with the deterministic, explainable ranking
from the spec — trigger for **ADR-005 (personalization model)**.

## Scope

- Preference model per §8.1: `residence_country, residence_region,
  home_state, home_city, topics[], language, notification_mode`, sourced
  from onboarding (T14/T15) and editable via `PATCH /v1/me/preferences`.
- Ranking formula, exactly as specified in §8.2 (do not substitute a
  different formula or an ML model without an ADR):
  `score = 0.28*residence + 0.20*home + 0.18*topic + 0.16*freshness +
  0.14*importance + 0.04*source_quality - repetition_penalty`.
- "Why this matters" per audience segment (§8.3): generate once per
  story/segment via the AI gateway (T10) and cache — never a fresh LLM call
  per feed request. Cache key should be `(story_id, segment)`.
- Explainability per §8.4: every personalized recommendation is attributable
  to an explicit signal shown to the user, e.g. "Because you live in the USA
  and follow Immigration" — derive this from the actual scoring inputs, not
  a generic canned string.
- Write ADR-005 recording the ranking approach and explicitly noting it's
  deterministic by design for V1 (no black-box ML ranking).

## Acceptance criteria

- ADR-005 exists and is accepted.
- Given fixed preferences and a fixed story set, the feed order is
  deterministic and reproducible across runs (no randomness/model variance).
- Requesting the same story/segment's "why this matters" twice does not
  trigger two AI calls — verify via cost telemetry from T10.
- Each personalized feed item has an explanation string that traces to an
  actual matched preference signal, verifiable in tests.
