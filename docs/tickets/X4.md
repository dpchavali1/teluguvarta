# X4 — X monitoring and budget guard

**Depends on**: X3, T18. **Insert after**: X3 and T18.

## Goal

Give admins visibility and control over X ingestion cost/health,
independent of the rest of the system.

## Scope

- Admin view (extends T18's observability work) showing per-X-account:
  health state, last poll time, current `since_id`, recent errors, cost
  usage, active/paused state.
- Budget guard: when the configured X monthly/daily budget threshold is
  reached, reduce or pause **low-priority** polling first — never take
  unrelated ingestion (other sources, higher-priority X accounts) offline as
  a side effect.
- Manual pause/resume control per X account in admin, separate from the
  general per-source kill switch pattern from T06 if a finer-grained control
  is warranted (reuse T06's mechanism if it's already sufficient — don't
  duplicate for its own sake).

## Acceptance criteria

- Admin can see, per X account, health/poll-state/`since_id`/errors/cost/
  active-state without reading logs directly.
- Simulated budget-threshold breach pauses/reduces only low-priority X
  polling and does not affect other sources or higher-priority accounts
  (explicit test).
- Manual pause of one X account doesn't affect any other account's polling.
