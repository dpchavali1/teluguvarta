# T03 — Database schema

**Depends on**: T02.

## Goal

Implement the full V1 core data model as immutable migrations.

## Scope

Implement every entity in `docs/SPEC.md` §12 as tables/migrations: `User,
Profile, Topic, UserTopic, Source, SourceItem, Story, StoryVariant,
StorySource, StoryEntity, Entity, EntityAlias, StoryTopic, ReviewTask,
Correction, Notification, Job, AuditEvent`. Include:

- The `Source.rights_status` enum: `DISABLED | LINK_ONLY |
  LICENSED_METADATA | LICENSED_REPURPOSE`, defaulting to `DISABLED` at the
  DB level (not just app level — this is a non-negotiable, enforce it as
  close to the data as possible).
- The `Story.status` publication state machine from §12.1: `DRAFT ->
  AI_READY -> REVIEW_REQUIRED -> APPROVED -> SCHEDULED -> PUBLISHED ->
  UPDATED`, `PUBLISHED -> RETRACTED`, `UPDATED -> CORRECTION_PENDING ->
  UPDATED`. Encode legal transitions with a check constraint or an
  application-level guarded transition function — pick one and note the
  choice in a code comment (not a full ADR, this is a normal implementation
  choice).
- `Job` table shaped for the Postgres-backed queue pattern from §14:
  `status, run_after, attempts, lock_expiry, dedupe_key` plus `type,
  payload, locked_at, last_error`. This is what T08 will consume.
- Appropriate indexes: at least `Story.canonical_slug` (unique),
  `SourceItem(source_id, external_id)` (unique, for dedupe),
  `Job(status, run_after)` (for claiming), `pg_trgm` index for future search
  on `StoryVariant.headline`/`summary`.
- Migrations must be immutable once applied — every later schema change is a
  new migration file, never an edit to an existing one.

## Out of scope

No API endpoints yet (T04+). No seed data beyond what's needed for migration
tests.

## Acceptance criteria

- All tables/enums/constraints from §12 exist and match field lists.
- Migration test: apply all migrations to a clean DB, verify schema; apply +
  rollback (if the tool supports it) without error.
- A test asserts illegal state transitions (e.g. `DRAFT -> PUBLISHED`
  directly) are rejected.
- A test asserts a `Source` row cannot be created with a rights_status other
  than the four enum values, and defaults to `DISABLED` when unspecified.
