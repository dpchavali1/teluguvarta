# S1 — Student life-stage profile

**Depends on**: T03 (schema), T14/T15 (surfaces to extend). **Insert after**:
whichever of those has landed; this can start as soon as the schema exists
and land its UI pieces incrementally in T14/T15's scope if built
concurrently, or as a follow-up ticket if T14/T15 already shipped.

## Goal

Make International Student / Graduate-OPT a first-class life stage using
the existing feed/notification systems — never a parallel backend (hard
constraint #13).

## Scope

- Onboarding per §3.1/§3.5: life-stage selection includes International
  Student, Graduate/OPT, Professional, Family/Parent, Other. If
  International Student is selected, optionally collect study
  country/state/region/metro and degree level. **Do not** require
  university name or immigration-document data for personalization.
- "Student Briefing" module/view: combines immigration, education, jobs,
  money, travel, campus/community, and India/home-region stories using the
  same ranking (T16) and feed rendering — implement as a filtered/composed
  view over the existing feed, not a separate content pipeline.
- Explicit-preference-only rule (§3.5, non-negotiable-adjacent): never infer
  immigration/visa status or other sensitive attributes from reading
  behavior — student signals come only from what the user explicitly
  selected in Settings/onboarding.

## Acceptance criteria

- Selecting International Student or Graduate/OPT surfaces the Student
  Briefing module on both web and mobile, composed from the same feed data
  source as the regular home feed.
- No code path infers life-stage or immigration-adjacent attributes from
  click/read behavior — verify by grepping for any such inference logic
  during review; none should exist.
- Skipping all student-specific onboarding questions still produces a
  working (if less personalized) feed.
