# T17 — Push notifications

**Depends on**: T16.

## Goal

Implement daily briefing, topic alerts, and gated breaking alerts with
strict deduplication and quiet-hours/cap enforcement.

## Scope

- Token registration via `POST /v1/me/push-tokens`; delivery through
  FCM/APNs via Expo/React Native tooling per §10.1.
- Topic alerts per §9.4: a story is eligible only if it matches at least one
  topic/geography/entity preference the user actually selected, plus the
  notification quality threshold. Never send a topic alert for an unrelated
  high-engagement category.
- Breaking alerts as a **separate path** (§9.4): sendable without an
  explicit topic subscription only when urgency, confidence, policy, source
  quality, and editorial thresholds all pass — sensitive categories stay
  human-gated (never auto-sent) per the non-negotiables.
- Notification controls (§3.1/§9.4): per-topic toggles, breaking on/off,
  daily-briefing on/off, quiet hours, max alerts/day, notification history;
  defaults favor low frequency/high relevance.
- `notification_dispatch` worker (§14): batch users, compute story-level
  eligibility once (not per-user AI calls), match deterministic preferences,
  apply quiet hours and daily caps, dedupe by `user_id + notification_key`,
  capped-backoff retries that never create duplicates.
- Deep links (§9.4): every notification carries a destination type/id;
  opening it goes to the intended story/topic page; if retracted/expired/
  unavailable, fall back to the inbox or home feed.
- Delivery-target awareness: normal stories should already be live within 15
  min of discovery (T08/T11 pipeline); breaking candidates evaluated within
  3 min; approved breaking pushes dispatched within 1 min of approval — this
  ticket's dispatch logic must not be the bottleneck.
- Analytics events per §9.4: `story_share, share_channel,
  notification_received, notification_open,
  notification_skipped_due_to_quiet_hours,
  notification_suppressed_by_daily_cap, notification_failed`.

## Acceptance criteria

- A user subscribed only to "Money" never receives a topic alert for an
  unrelated "Entertainment" story, however high its engagement (explicit
  negative test).
- Breaking-alert eligibility is computed via a separate code path from
  topic-alert eligibility, and a sensitive-category story never triggers an
  auto-sent breaking alert.
- Sending the same notification twice (retry/duplicate trigger) never
  produces two deliveries to the same user (dedupe key test).
- Quiet hours and daily caps are enforced and generate the corresponding
  analytics events instead of silently dropping the send.
- A deep link to a retracted story falls back gracefully instead of erroring.
