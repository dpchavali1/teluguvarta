# T20 — Pilot

**Depends on**: T19.

## Goal

Run the real-world pilot and produce a go/no-go decision for public launch
— this is a product/ops-heavy ticket, not pure engineering, but Claude Code
supports it with instrumentation and fixes.

## Scope

- Confirm the pre-build validation gate (`docs/BUILD_ORDER.md` "Pre-build
  validation gate") was actually run; if it wasn't, flag this loudly before
  proceeding — running a 50-100 user pilot on unvalidated positioning
  compounds the risk.
- Recruit/onboard 50-100 target users (product/ops responsibility, not
  Claude Code's, but ensure onboarding/analytics from T14/T15/T18 supports
  it).
- Collect the north-star and supporting metrics from §17 throughout the
  pilot window; fix friction issues surfaced (bugs, confusing onboarding
  steps, notification tuning) as normal bug-fix tickets referencing this
  one.
- Verify the full launch checklist from §26 (`docs/SPEC.md` §26 has the
  complete list) — share/notification behavior, source rights approvals
  documented, legal pages counsel-reviewed where required, admin staffed for
  sensitive review, EN/Telugu QA thresholds, backup/deletion tests, app-store
  form accuracy, student and X-adapter acceptance criteria if X1-X4/S1-S2
  have been built.
- Document the go/no-go decision and rationale (repeat weekly usage +
  qualitative utility evidence, per §1.5) in a short pilot report — this is
  the kind of durable record that belongs in the repo (e.g.
  `docs/runbooks/pilot-report.md`), not only in conversation history.

## Acceptance criteria

- Pilot metrics are actually being captured (verify via T18's analytics, not
  assumed).
- Every item on the §26 launch checklist relevant to what's been built is
  checked off or explicitly deferred with a reason.
- A pilot report exists in the repo with the go/no-go decision and
  supporting data.
