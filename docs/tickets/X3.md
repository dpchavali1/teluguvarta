# X3 — X post to story pipeline

**Depends on**: X2, T09. **Insert after**: X2 and T09.

## Goal

Route X posts through the exact same rights/editorial pipeline as any other
source — the whole point of this ticket is that X gets **no special
treatment**.

## Scope

- Convert fetched X posts into `SourceItem`s (X post ID as the dedupe key,
  canonical X URL, author/handle, `created_at`, permitted metadata only)
  through the standard adapter `emit()` contract from T07.
- Route through the same rights gate, dedupe, clustering (T09), AI
  classification/summary (T11), and editorial review (T12) as every other
  source. **A single X post must never bypass review just because the
  account is official** (§6.3.1, non-negotiable #4/#12).
- Do not copy full X post text, images, or video into the published story
  unless current X Developer Terms/API policy and applicable rights
  explicitly permit it — default to an original summary + attribution, same
  as any other `LICENSED_METADATA`/`LINK_ONLY` source.
- Preserve canonical attribution: the published story must link back to the
  original X post/account, not just say "X" generically.

## Acceptance criteria

- An X-derived story from a `DISABLED` X account never reaches `PUBLISHED`
  (same test pattern as T08's non-X rights-gate test, applied to X).
- An X post classified as breaking/immigration/legal/financial requires
  human approval exactly like any other source's story — no
  official-account shortcut exists in code.
- A published X-derived story shows canonical attribution to the source
  account/post, verifiable in the rendered story page.
- Duplicate fetches of the same X post never create duplicate `SourceItem`
  or `Story` rows.
