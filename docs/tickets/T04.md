# T04 — OpenAPI contracts

**Depends on**: T03.

## Goal

Establish the typed contract between `apps/api` and every client
(`apps/web`, `apps/mobile`, `apps/admin`), generated automatically so it
can never silently drift.

## Scope

- Implement the endpoint shapes from `docs/SPEC.md` §13 in FastAPI
  (request/response Pydantic models only — real business logic lands in
  later tickets, these can return minimal/stub data initially where a
  dependency ticket hasn't landed yet, but the *shape* must be final):
  - Public: `GET /v1/home`, `GET /v1/stories`, `GET /v1/stories/{slug}`,
    `GET /v1/topics/{slug}`, `GET /v1/search?q=...`, `GET /v1/config`,
    `GET /v1/stories/{slug}/share-meta`.
  - Authenticated: `GET /v1/me`, `PATCH /v1/me/preferences`,
    `POST /v1/me/saved/{story_id}`, `DELETE /v1/me/saved/{story_id}`,
    `POST /v1/me/push-tokens`, `DELETE /v1/me/account`.
  - Admin: `GET /v1/admin/sources`, `PATCH /v1/admin/sources/{id}`,
    `GET /v1/admin/review-queue`, `POST /v1/admin/stories/{id}/approve`,
    `POST /v1/admin/stories/{id}/reject`,
    `POST /v1/admin/stories/{id}/retract`,
    `POST /v1/admin/stories/{id}/correct`, `GET /v1/admin/jobs`,
    `GET /v1/admin/audit`.
- Standard error envelope everywhere: `{ "error": { "code", "message",
  "request_id" } }`. Add this as shared middleware/exception handler, not
  per-endpoint.
- Generate `packages/contracts` TypeScript types from the FastAPI OpenAPI
  schema on every build (CI step: fail the build if generated types are
  stale vs. committed types, so contract drift is caught immediately).
- `apps/web`, `apps/mobile`, `apps/admin` import types only from
  `packages/contracts` — never hand-roll parallel type definitions for API
  shapes.

## Acceptance criteria

- OpenAPI schema is generated and valid; `packages/contracts` types compile.
- CI fails if someone changes an API model without regenerating contracts.
- Every endpoint above exists (even if backed by stub/placeholder data) and
  returns the documented error envelope on failure.
